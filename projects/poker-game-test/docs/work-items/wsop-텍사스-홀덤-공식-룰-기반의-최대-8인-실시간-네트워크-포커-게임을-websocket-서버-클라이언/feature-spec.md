2026-05-08T00:04:21\n\n## Feature Overview\n\nWSOP 텍사스 홀덤 공식 룰 기반의 최대 8인 실시간 네트워크 포커 게임을 WebSocket 서버-클라이언트 분리 구조로 구현한다.\n\n## User Scenarios\n\n- 플레이어: 브라우저에서 URL 접속 → 시스템: 로비 화면 표시, 닉네임 입력 요청\n- 플레이어: 닉네임 입력 후 방 생성 또는 입장 → 서버: WebSocket 연결 수립, 대기실 상태 브로드캐스트\n- 2명 이상 입장 후 호스트: 게임 시작 클릭 → 서버: 덱 셔플, 홀카드 배분, 블라인드 강제 징수 후 프리플랍 시작\n- 액티브 플레이어: 베팅 액션 버튼(폴드/체크/콜/레이즈/올인) 클릭 → 서버: 액션 검증·상태 갱신·다음 플레이어 턴 브로드캐스트\n- 라운드 종료: 서버가 쇼다운 판정 → 승자 결정·팟 지급·다음 라운드 준비 후 전체 클라이언트에 결과 브로드캐스트\n- 플레이어: 칩 소진 → 서버: 해당 플레이어 게임 아웃 처리, 사이드팟 재계산 후 나머지 플레이어에게 통보\n- 플레이어: 브라우저 닫기/연결 끊김 → 서버: 해당 턴에 자동 폴드 처리, 접속 복귀 불가(세션 내 게임만)\n\n## Functional Requirements\n\n- [텍사스 홀덤 룰 엔진] 텍사스 홀덤 룰 엔진 (핸드 평가·팟·사이드팟 계산·턴 진행)을(를) 구현한다.\n- [8인 실시간 게임 서버] 8인 실시간 게임 서버 (WebSocket 기반)을(를) 구현한다.\n- [반응형 HTML5 게임 클라이언트] 반응형 HTML5 게임 클라이언트 (모바일·PC·태블릿)을(를) 구현한다.\n- [방 생성·입장·대기 로비 UI] 방 생성·입장·대기 로비 UI을(를) 구현한다.\n- [게임 진행 화면] 게임 진행 화면 (커뮤니티카드·홀카드·베팅 액션 표시)을(를) 구현한다.\n- [베팅 액션 UI] 베팅 액션 UI (콜·레이즈·폴드·체크·올인)을(를) 구현한다.\n- [Backend Dev 구현] 서버, 데이터, 외부 연동 레이어를 구현한다.\n- [Game Logic Dev 구현] 핵심 규칙과 상태 전이를 구현한다.\n- [QA Engineer 검증] 핵심 플로우와 회귀 시나리오를 검증한다.\n\n## Non-Functional Requirements\n\n- **성능**: 베팅 액션 수신 후 전체 클라이언트 브로드캐스트까지 500ms 이하 (로컬 네트워크 기준)\n- **동시성**: 방당 WebSocket 연결 최대 8개 유지; 연결 끊김 감지 즉시 자동 폴드 처리\n- **호환성**: Chrome 90+, Safari 14+, Firefox 88+, Edge 90+ — 별도 플러그인·앱 설치 불필요\n- **반응형**: 화면 너비 320px~2560px 전 범위 대응 (모바일·태블릿·PC 단일 코드베이스)\n- **보안**: 모든 게임 판정(핸드 비교·팟 계산·턴 진행)은 서버 전담 — 클라이언트 단에서 상태 위조 불가\n- **상태 일관성**: 서버가 Single Source of Truth; 클라이언트는 서버 브로드캐스트 수신 시에만 UI 갱신\n\n## Inputs and Outputs\n\n- **GameRoom** [memory]: room_id, players, deck, community_cards, pot, side_pots\n- **Player** [memory]: player_id, nickname, chips, hole_cards, current_bet, is_folded\n- **SidePot** [memory]: amount, eligible_player_ids\n- **GameAction** [memory]: player_id, action_type, amount, timestamp\n\n## Exceptions and Failure Scenarios\n\n- **플레이어 연결 끊김** (브라우저 닫기·네트워크 단절): 해당 턴 자동 폴드 처리 후 이후 턴 건너뜀; 세션 복귀 불가 — 재접속 시 새 플레이어로 취급\n- **칩 소진 올인 후 패배**: 해당 플레이어 즉시 게임 아웃; 기여 금액 상한 기준 사이드팟 자동 재계산 후 나머지 플레이어에게 브로드캐스트\n- **유효하지 않은 베팅 액션** (보유 칩 초과 레이즈, 최소 레이즈 미만 등): 서버가 `action_rejected` 메시지 반환; 클라이언트 베팅 UI 초기화, 해당 플레이어 턴 유지\n- **게임 시작 시 활성 플레이어 2명 미만**: 서버가 시작 거부 후 `start_rejected` 사유 브로드캐스트; 호스트가 추가 입장 대기\n- **방 최대 인원(8명) 초과 입장 시도**: 서버가 `room_full` 메시지 반환; 신규 WebSocket 연결 즉시 종료\n- **게임 진행 중 중복 닉네임 입장 시도**: 서버가 `nickname_taken` 메시지 반환; 클라이언트 닉네임 재입력 요청\n\n## Existing Behavior To Preserve\n\n신규 구현 프로젝트로 보존해야 할 기존 코드·동작 없음. 단, 구현 과정에서 확립되는 아래 아키텍처 불변식은 이후 기능 추가 시에도 반드시 유지한다:\n\n- 게임 상태 전이는 서버에서만 발생 — 클라이언트가 직접 상태를 변경하는 경로 추가 금지\n- 클라이언트는 서버 브로드캐스트 메시지만 소비하고 렌더링에만 사용 — 게임 판정 로직 이식 금지\n- 초기 칩(1,000), 스몰 블라인드(10), 빅 블라인드(20) 고정값은 서버 설정 파일에서 단일 출처로 관리\n\n## Acceptance Criteria\n\n- 텍사스 홀덤 룰 엔진의 핵심 기능이 구현된다.\n- 관련 파일과 산출물이 갱신된다.\n- 검증 결과가 정리된다.\n- 잔여 리스크와 후속 작업이 기록된다.\n- 8인 실시간 게임 서버의 핵심 기능이 구현된다.\n- 반응형 HTML5 게임 클라이언트의 핵심 기능이 구현된다.\n- 방 생성·입장·대기 로비 UI의 핵심 기능이 구현된다.\n- 게임 진행 화면의 핵심 기능이 구현된다.\n- 베팅 액션 UI의 핵심 기능이 구현된다.\n- Backend Dev 구현의 핵심 기능이 구현된다.\n- Game Logic Dev 구현의 핵심 기능이 구현된다.\n- QA Engineer 검증의 핵심 기능이 구현된다.\n\n## Evidence\n\n- Local reference:
