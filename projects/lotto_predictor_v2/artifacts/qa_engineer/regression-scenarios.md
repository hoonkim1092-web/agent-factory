## 회귀 시나리오
### R1. 증분 수집 재실행
- 목적: 이미 수집한 회차 이후만 추가 수집하는지 확인
- 입력: 기존 체크포인트가 있는 캐시, 최신 회차보다 작은 마지막 회차
- 기대 결과:
  - 기존 회차는 중복 저장되지 않는다.
  - 새 회차만 추가되고 체크포인트가 갱신된다.

### R2. 캐시 기반 복구
- 목적: 네트워크 장애 시 로컬 캐시 fallback이 유지되는지 확인
- 입력: 네트워크 실패 상태, 유효한 로컬 캐시
- 기대 결과:
  - 수집 단계는 실패 원인을 기록한다.
  - 분석/추천은 캐시 기반으로 계속 진행되거나 명확히 중단된다.

### R3. 분석 결과 형식 안정성
- 목적: 출력 필드가 누락되지 않는지 확인
- 입력: 최근 500회차 데이터
- 기대 결과:
  - 빈도, 추세, 홀짝, 구간 분포 필드가 모두 존재한다.
  - 리포트/구조화 출력의 섹션 이름이 변경되지 않는다.

### R4. 동일 seed 재현성
- 목적: 추천기가 동일 입력에 대해 동일 결과를 유지하는지 확인
- 입력: 동일 회차 범위, 동일 `seed`, 동일 개수 요청
- 기대 결과:
  - 1차/2차 결과 조합이 완전히 동일하다.
  - 조합 순서도 동일하다.

### R5. 범위 및 중복 규칙
- 목적: 추천 숫자 규칙이 깨지지 않는지 확인
- 입력: 임의의 추천 실행
- 기대 결과:
  - 모든 숫자는 1~45 범위다.
  - 한 조합 안에 중복 숫자가 없다.
  - 조합 수가 요청값과 일치한다.

### R6. 리포트 고정 섹션 유지
- 목적: 사용자 가시 출력의 핵심 섹션이 유지되는지 확인
- 입력: 표준 실행 결과
- 기대 결과:
  - 제목, 기준 데이터, 통계 요약, 추천 조합, 면책 고지 섹션이 모두 있다.
  - 문구가 한국어로 제공된다.

### R7. 빌드 산출물 경로 유효성
- 목적: 배포 경로와 문서 경로가 어긋나지 않는지 확인
- 입력: `dist/` 하위 산출물과 사용자 가이드
- 기대 결과:
  - 가이드에 적힌 파일명/경로/실행 순서가 실제 산출물과 일치한다.

## 실패 시나리오
### F1. 외부 API 응답 실패
- 트리거: `returnValue != "success"` 또는 HTTP 오류
- 기대 처리:
  - 실패 원인을 한국어로 기록한다.
  - 재시도 또는 캐시 fallback 여부가 명확하다.

### F2. 분석 입력 부족
- 트리거: 캐시에 500회차 미만 데이터만 존재
- 기대 처리:
  - 분석 불가 또는 축소 분석 여부가 명확히 표시된다.
  - 침묵 실패 없이 원인을 출력한다.

### F3. 추천 후보 부족
- 트리거: 규칙 충돌로 목표 조합 수를 만들지 못함
- 기대 처리:
  - 실패 또는 완화 여부가 결과에 기록된다.
  - 누락된 조합 수를 숨기지 않는다.

### F4. 리포트 렌더링 누락
- 트리거: 필수 섹션 또는 면책 고지가 빠짐
- 기대 처리:
  - QA 결과는 즉시 `FAIL` 처리한다.

### F5. 빌드 산출물 누락
- 트리거: `dist/` 파일 또는 실행 파일이 없음
- 기대 처리:
  - 경로와 누락 항목을 기록하고 verify 단계로 넘긴다.
