## 설계 의도
- 통계 모듈이 계산한 5가지 패턴 결과를 단일 입력 타입 `PatternStats`로 묶어 추천기가 직접 소비하게 한다.
- 추천기는 무작위 추출이 아니라 결정적 조합 생성과 가중치 점수화로 상위 후보를 반환한다.
- 제약은 후보 생성 단계에서 강제하고, 점수는 후보 우선순위 결정에만 사용한다.

## 인터페이스 제안
### 입력
- `PatternStats`
  - `number_frequency`
  - `consecutive_gaps`
  - `odd_even_ratio`
  - `section_distribution`
  - `trend_weights`

### 출력
- `recommend_combinations(stats: PatternStats, n_combinations: int = 5) -> list[Combination]`
- `Combination`
  - `numbers`
  - `score`
  - `odd_even_ratio`
  - `section_distribution`

## 구현 방침
1. 빈도 내림차순, 트렌드 보조 정렬로 상위 70% 번호 풀을 고정한다.
2. 후보 풀에서 가능한 6개 조합을 열거한다.
3. 홀짝 비율과 구간 균형 제약을 먼저 적용한다.
4. 빈도, 트렌드, 연속 등장 간격, 구간 균형 패널티를 합산해 점수화한다.
5. 점수 내림차순으로 정렬해 상위 `n_combinations`개를 반환한다.

## 대안 검토
### 대안 A. 무작위 샘플링 기반 추천
- 장점: 구현이 단순하다.
- 단점: 같은 입력에서 결과가 흔들리고 테스트가 불안정하다.
- 결론: 채택하지 않음.

### 대안 B. 전체 조합 열거 후 결정적 정렬
- 장점: 규칙 위반 여부를 명확히 검증할 수 있고 재현 가능하다.
- 단점: 후보 풀이 커지면 계산량이 증가한다.
- 결론: 채택. 상위 70% 풀로 후보 수를 제한해 비용을 제어한다.
