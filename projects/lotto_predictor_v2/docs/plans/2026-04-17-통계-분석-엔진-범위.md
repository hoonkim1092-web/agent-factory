## 공개 인터페이스
```text
analyze_patterns(draws: Sequence[object]) -> PatternStats
build_pattern_stats_from_cache(cache: LottoDrawCache, draw_limit: int = 500) -> PatternStats
summarize_analysis_run(stats: PatternStats, source_draw_count: int, latest_draw_no: int) -> AnalysisRunSummary
```

## 입력 계약
### `analyze_patterns`
- `draws`는 길이 1 이상 500 이하의 시퀀스여야 한다.
- 정렬 기본값은 최신 회차부터 과거 회차 순이다.
- 각 항목은 길이 6의 정수 시퀀스이거나 `numbers` 속성을 가진 객체여야 한다.
- 모든 번호는 `1..45` 범위의 중복 없는 정수여야 한다.

### `build_pattern_stats_from_cache`
- `cache`는 `LottoDrawCache` 공개 API만 사용한다.
- 기본 입력은 `cache.get_recent_draws(500)` 이다.
- 캐시가 비어 있으면 `ValueError` 를 반환한다.
- 캐시 정렬 방향은 내림차순(최신순)으로 가정하되, build 단계에서 방어 검증을 추가한다.

## 출력 계약
### `PatternStats`
- `number_frequency`: `1..45` 전체 번호의 누적 출현 횟수
- `consecutive_gaps`: 번호별 `gaps`, `average_gap`, `last_gap`, `appearance_count`
- `odd_even_ratio`: `ratio_counts`, `dominant_ratio`, `dominant_count`, `average_odd_count`, `average_even_count`
- `section_distribution`: `1-10`, `11-20`, `21-30`, `31-40`, `41-45`
- `trend_weights`: 최신 회차 우선 선형 가중치 점수

### `AnalysisRunSummary`
- `source_draw_count`: 실제 분석에 사용한 회차 수
- `latest_draw_no`: 분석 기준 최신 회차 번호
- `oldest_draw_no`: 분석 기준 최저 회차 번호
- `dominant_ratio`: 대표 홀짝 비율
- `top_frequency_numbers`: 빈도 상위 번호 목록
- `generated_at`: 분석 요약 생성 시각

## 오류 계약
- `TypeError`: 입력 시퀀스 구조가 잘못됐거나 번호가 정수가 아닐 때
- `ValueError`: 회차 목록이 비어 있거나 500건을 초과할 때, 번호 개수/범위/중복이 잘못됐을 때

## 구현 순서
1. `PatternStats` 와 `AnalysisRunSummary` 출력 계약을 고정한다.
2. 공통 입력 검증 및 회차 정규화 헬퍼를 구현한다.
3. 빈도, 연속 간격, 홀짝, 구간, 트렌드 계산 함수를 구현한다.
4. `analyze_patterns()` 로 5개 통계를 묶어 반환한다.
5. `build_pattern_stats_from_cache()` 로 캐시 연결 어댑터를 구현한다.
6. `summarize_analysis_run()` 과 통합 테스트 골격을 정리한다.

## 대안 검토
### 대안 A. 캐시 계층 안에서 직접 통계 계산
- 장점: 호출 단계가 줄어든다.
- 단점: 캐시의 책임이 정책/조회에서 계산까지 확장되어 module_2와 module_3 경계가 무너진다.
- 결론: 채택하지 않음.

### 대안 B. 통계 계산과 캐시 어댑터를 분리한 함수형 모듈
- 장점: 순수 계산 함수 테스트와 캐시 연결 테스트를 분리할 수 있다.
- 단점: 공개 함수 수가 늘어난다.
- 결론: 채택. build 단계에서 순수 계산과 연결 어댑터를 분리한다.
