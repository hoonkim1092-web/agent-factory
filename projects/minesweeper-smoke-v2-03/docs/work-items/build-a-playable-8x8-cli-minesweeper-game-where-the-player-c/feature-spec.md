## Feature Overview

8×8 고정 그리드의 CLI 지뢰찾기 게임을 Python 3.11 표준 라이브러리만으로 구현한다. 플레이어는 터미널에서 좌표를 입력해 셀을 공개하거나 지뢰에 깃발을 꽂으며, 모든 비지뢰 셀을 공개하면 승리, 지뢰 셀을 공개하면 패배한다. 이 게임은 Agent Factory 작업 항목 병렬 측정 파이프라인의 경량 기준선(baseline) 태스크로, 외부 의존성 없이 단일 터미널 세션에서 완결된다.

## User Scenarios

### 시나리오 1 — 정상 게임 플로우 (승리)

1. 플레이어가 `python3 minesweeper.py` 또는 `python3 minesweeper.py --mines 10`으로 게임을 시작한다.
2. 시스템이 8×8 빈 보드와 좌표 입력 프롬프트를 출력한다.
3. 플레이어가 첫 번째 좌표를 입력한다 (예: `3 4`).
4. 시스템이 해당 셀에 지뢰를 배치하지 않고 보드를 초기화한 뒤 공개한다. 인접 지뢰 수가 0이면 연쇄 공개가 발생한다.
5. 플레이어가 반복하여 셀을 공개하다가 비지뢰 셀 전체가 공개되면 시스템이 승리 메시지를 출력하고 종료한다.

### 시나리오 2 — 지뢰 셀 공개 (패배)

1. 플레이어가 지뢰가 있는 셀의 좌표를 입력한다.
2. 시스템이 게임 오버 메시지와 함께 전체 지뢰 위치를 보드에 표시하고 종료한다.

### 시나리오 3 — 깃발 토글

1. 플레이어가 `f 2 5`를 입력한다.
2. 시스템이 해당 셀에 깃발을 표시한다.
3. 이미 깃발이 있는 셀에 동일 명령을 입력하면 깃발이 해제된다.
4. 깃발이 꽂힌 셀은 공개 명령을 무시한다.

### 시나리오 4 — 사용자 정의 지뢰 수

1. 플레이어가 `python3 minesweeper.py --mines 15`로 실행한다.
2. 시스템이 15개의 지뢰로 게임을 시작한다.

### 시나리오 5 — 잘못된 입력

1. 플레이어가 범위를 벗어난 좌표(예: `9 0`) 또는 형식 오류(예: `abc`)를 입력한다.
2. 시스템이 오류 메시지를 출력하고 재입력을 요청한다. 게임 상태는 변경되지 않는다.

## Functional Requirements

### FR-01 그리드 초기화

- 게임 시작 시 8×8 크기의 빈 보드를 생성한다.
- 모든 셀은 `is_revealed=False`, `is_flagged=False`, `is_mine=False`, `adjacent_count=0` 상태로 초기화된다.

### FR-02 안전 첫 클릭 (safe-first-click)

- 첫 번째 입력 좌표에는 지뢰를 배치하지 않는다.
- 지뢰 배치는 첫 번째 셀 공개 명령이 처리된 직후에 수행된다.

### FR-03 지뢰 랜덤 배치

- 첫 클릭 셀을 제외한 나머지 63개 위치 중 `mine_count`개를 무작위로 선택해 지뢰를 배치한다.
- `mine_count` 기본값은 10이며, 허용 범위는 1 이상 63 이하의 정수이다.

### FR-04 인접 지뢰 수 계산

- 지뢰 배치 후 비지뢰 셀 각각에 대해 8방향 이웃 셀 중 지뢰 수를 세어 `adjacent_count`에 저장한다.

### FR-05 재귀적 셀 공개 (flood reveal)

- 플레이어가 공개한 셀의 `adjacent_count`가 0이면, 이웃하는 미공개·비지뢰 셀을 재귀적으로 공개한다.
- 재귀 진입 전 `0 ≤ row < 8`, `0 ≤ col < 8` 범위 검사를 수행하여 경계 초과를 방지한다.
- 이미 공개된 셀 또는 깃발이 꽂힌 셀은 재귀 대상에서 제외한다.

### FR-06 깃발 토글

- `f <row> <col>` 명령으로 미공개 셀에 깃발을 표시하거나 기존 깃발을 해제한다.
- 이미 공개된 셀에는 깃발을 꽂을 수 없다.

### FR-07 승리 판정

- 비지뢰 셀 전체(64 − mine_count개)가 공개 상태(`is_revealed=True`)가 되면 게임 상태를 `WIN`으로 전환한다.
- 승리 메시지와 함께 최종 보드를 출력하고 프로그램을 종료한다.

### FR-08 패배 판정

- 지뢰 셀(`is_mine=True`)이 공개되면 게임 상태를 `LOSE`로 전환한다.
- 패배 메시지를 출력하고 전체 지뢰 위치가 노출된 보드를 출력한 뒤 프로그램을 종료한다.

### FR-09 ASCII 보드 렌더링

- 매 턴 입력 처리 후 현재 보드 상태를 터미널에 출력한다.
- 셀 표시 규칙:

| 상태 | 표시 문자 |
|------|-----------|
| 미공개 | `#` |
| 깃발 | `F` |
| 공개 (지뢰 수 > 0) | `1`~`8` (인접 지뢰 수) |
| 공개 (지뢰 수 = 0) | `.` |
| 지뢰 (패배 시 노출) | `*` |

- 행·열 번호를 포함한 인덱스를 보드 상단과 좌측에 표시한다.

### FR-10 CLI 진입점 및 인수 파싱

- `python3 minesweeper.py` 명령으로 실행된다.
- `--mines <int>` 선택적 인수로 지뢰 수를 지정한다. 생략 시 기본값 10을 사용한다.
- `quit` 또는 `q` 입력 시 게임을 즉시 종료한다.

### FR-11 입력 검증

- 좌표는 `<row> <col>` 형식으로 입력한다. 0 기반 또는 1 기반 중 하나를 일관되게 사용하고 프롬프트에 명시한다.
- 범위 벗어난 좌표, 숫자가 아닌 입력, 이미 공개된 셀 공개 시도는 오류 메시지를 출력하고 재입력을 요청한다.

## Non-Functional Requirements

### NFR-01 의존성

- Python 3.11 표준 라이브러리(`random`, `sys`, `os`)만 사용한다. 서드파티 패키지는 불허한다.
- pytest 7.x는 테스트 전용으로만 사용하며, 게임 실행에는 관여하지 않는다.

### NFR-02 실행 환경

- 단일 터미널 세션에서 게임 시작부터 종료까지 가능해야 한다.
- 웹 서버, 브라우저, 외부 네트워크 연결이 필요 없다.

### NFR-03 성능

- 8×8 그리드 규모에서 flood reveal을 포함한 모든 연산은 100ms 이내에 완료되어야 한다.

### NFR-04 재현성

- 동일한 seed 값이 주어진 경우, 동일한 지뢰 배치가 생성되어야 한다. (선택적 `--seed <int>` 인수)

### NFR-05 코드 구조

- `minesweeper.py`는 I/O와 게임 루프만 담당한다.
- 게임 상태 변경 로직(지뢰 배치, 공개, 판정)은 별도 함수 또는 클래스에 위임한다.
- 단일 파일로 제공하되, 내부 구조는 논리적 섹션으로 구분한다.

## Inputs and Outputs

### 입력

| 입력 | 형식 | 설명 |
|------|------|------|
| 실행 인수 | `--mines <int>` | 지뢰 수 (기본값: 10, 범위: 1~63) |
| 셀 공개 명령 | `<row> <col>` | 공개할 셀 좌표 |
| 깃발 명령 | `f <row> <col>` | 깃발 토글 좌표 |
| 종료 명령 | `quit` 또는 `q` | 게임 즉시 종료 |

### 출력

| 출력 | 시점 | 설명 |
|------|------|------|
| 보드 ASCII 렌더링 | 매 턴 입력 처리 후 | 현재 셀 상태 표시 |
| 입력 프롬프트 | 보드 출력 후 | 다음 명령 안내 |
| 오류 메시지 | 잘못된 입력 시 | 재입력 요청 |
| 승리 메시지 | WIN 상태 전환 시 | 게임 종료 안내 |
| 패배 메시지 + 전체 지뢰 노출 보드 | LOSE 상태 전환 시 | 게임 종료 안내 |

## Exceptions and Failure Scenarios

### EX-01 범위 초과 좌표 입력

- 원인: 플레이어가 `8 0`, `-1 3` 등 0~7 범위 밖의 좌표를 입력한다.
- 처리: 오류 메시지 출력 후 재입력 요청. 게임 상태 변경 없음.

### EX-02 형식 오류 입력

- 원인: 플레이어가 숫자가 아닌 문자(예: `abc`, `3 x`)를 입력한다.
- 처리: 오류 메시지 출력 후 재입력 요청. 게임 상태 변경 없음.

### EX-03 이미 공개된 셀 재공개 시도

- 원인: 플레이어가 이미 공개된 셀 좌표를 다시 입력한다.
- 처리: 오류 메시지 출력 후 재입력 요청.

### EX-04 공개된 셀에 깃발 시도

- 원인: 플레이어가 `f <row> <col>`로 이미 공개된 셀에 깃발을 꽂으려 한다.
- 처리: 오류 메시지 출력 후 재입력 요청.

### EX-05 잘못된 mine_count 인수

- 원인: `--mines 0`, `--mines 64`, `--mines abc` 등 허용 범위 밖 값이 입력된다.
- 처리: 오류 메시지 출력 후 프로그램 즉시 종료 (`sys.exit(1)`).

### EX-06 재귀 flood reveal 경계 초과

- 원인: 재귀 공개 중 그리드 경계(row < 0, row ≥ 8, col < 0, col ≥ 8)에 도달한다.
- 처리: 재귀 진입 전 범위 검사로 해당 셀을 건너뜀. 런타임 오류 없음.

## Existing Behavior To Preserve

이 work item은 신규 구현이므로 보존해야 할 기존 동작이 없다. 단, AF 파이프라인 계측 호환성을 유지하기 위해 다음 조건을 준수한다.

- `minesweeper.py`는 표준 입출력을 사용하여 터미널에서 직접 실행 가능해야 한다.
- 프로세스 종료 코드: 정상 종료(승리·패배 포함) 시 `0`, 인수 오류 시 `1`.

## Acceptance Criteria

### AC-01 게임 실행

- `python3 minesweeper.py`를 실행하면 8×8 보드가 출력되고 입력 프롬프트가 표시된다.
- `python3 minesweeper.py --mines 15`를 실행하면 15개의 지뢰로 게임이 시작된다.

### AC-02 안전 첫 클릭

- 첫 번째 입력 좌표의 셀은 지뢰가 아님을 단위 테스트로 검증한다.
- 첫 번째 입력 후에만 지뢰가 배치됨을 단위 테스트로 확인한다.

### AC-03 인접 지뢰 수 정확성

- 임의의 지뢰 배치에 대해 모든 비지뢰 셀의 `adjacent_count`가 실제 이웃 지뢰 수와 일치함을 단위 테스트로 검증한다.

### AC-04 flood reveal 종료 보장

- 코너 셀(0,0), 엣지 셀(0,4), 내부 셀(4,4)을 공개할 때 인덱스 오류 없이 재귀가 종료됨을 단위 테스트로 검증한다.

### AC-05 승리 판정

- 모든 비지뢰 셀이 공개된 직후 게임 상태가 `WIN`으로 전환됨을 단위 테스트로 검증한다.

### AC-06 패배 판정

- 지뢰 셀 공개 직후 게임 상태가 `LOSE`로 전환되고 전체 지뢰 위치가 보드에 표시됨을 단위 테스트로 검증한다.

### AC-07 깃발 토글

- 미공개 셀에 `f` 명령을 두 번 적용하면 깃발이 표시되었다가 해제됨을 단위 테스트로 검증한다.
- 깃발이 꽂힌 셀은 공개 명령에 반응하지 않음을 단위 테스트로 검증한다.

### AC-08 잘못된 입력 처리

- 범위 초과 좌표, 형식 오류 입력 시 게임 상태가 변경되지 않고 오류 메시지가 출력된다.

### AC-09 서드파티 의존성 없음

- `python3 minesweeper.py`가 표준 라이브러리만으로 실행되어 `ModuleNotFoundError` 없이 시작된다.

### AC-10 테스트 스위트 통과

- `pytest test_minesweeper.py` 실행 시 0 failures, 0 errors로 완료된다.
- 테스트는 최소 1개의 실제 실행 경로(비mock)를 포함한다.
