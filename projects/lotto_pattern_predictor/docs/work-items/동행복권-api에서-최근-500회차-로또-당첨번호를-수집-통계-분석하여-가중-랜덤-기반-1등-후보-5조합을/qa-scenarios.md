# QA 검증 시나리오

## 문서 목적
- QA Engineer `build` 단계에서 사용할 핵심 플로우 및 회귀 시나리오를 고정한다.
- `scripts/run_qa_checks.py`가 어떤 슬라이스를 실행해야 하는지 기준을 제공한다.

## 검증 슬라이스

### 1. 사전 조건 점검
- 목적: 검증 시작 전에 필요한 산출물과 실행 인터페이스가 준비되었는지 확인한다.
- 확인 항목:
  - CLI 엔트리포인트 파일 또는 실행 명령이 제공되었는가
  - SQLite 캐시 경로가 결정되었는가
  - `fetch`, `analyze`, `recommend` 실행 명령이 정의되었는가
  - 검증 결과를 저장할 출력 경로가 존재하거나 생성 가능한가
- 실패 분류: `환경 문제`

### 2. 모듈 계약 검증
- 목적: 핵심 모듈별 기대 입력과 출력 형식이 계약을 만족하는지 확인한다.
- 시나리오:
  - `fetch` 실행 결과에 회차 범위, 수집 건수, 저장 위치가 포함된다.
  - `analyze` 실행 결과에 번호 빈도, 동시 출현, 구간 통계 중 최소 1개 이상의 구조화된 요약이 포함된다.
  - `recommend` 실행 결과에 5개 조합이 출력되고 각 조합은 중복 없는 6개 번호를 가진다.
- 실패 분류:
  - `데이터 수집 실패`
  - `저장소 실패`
  - `분석 실패`
  - `추천 실패`

### 3. 종단간 회귀 검증
- 목적: `fetch -> analyze -> recommend` 흐름이 하나의 CLI 인터페이스로 연결되는지 확인한다.
- 시나리오:
  - 동일한 캐시 경로를 사용해 `fetch`, `analyze`, `recommend`를 순차 실행할 수 있다.
  - `analyze`는 `fetch` 이후 생성된 캐시를 읽는다.
  - `recommend`는 `analyze` 가능한 데이터가 준비된 상태에서 실패하지 않는다.
- 실패 분류:
  - `출력 포맷 실패`
  - 상기 모듈 실패 분류 중 최초 실패 항목

## 회귀 중점 항목
- `recommend --count 5` 기본값이 유지되는지 확인한다.
- 추천 조합 내 번호 중복이 없는지 확인한다.
- 캐시 경로 지정 시 후속 명령이 동일 경로를 재사용하는지 확인한다.
- `analyze`와 `recommend`가 오프라인 환경에서도 캐시 기반으로 실행 가능한 구조인지 확인한다.

## 실행 입력 규칙
- 실제 실행 명령은 환경에 따라 다를 수 있으므로 `scripts/run_qa_checks.py`의 CLI 인자로 주입한다.
- 실행 명령 미확정 상태에서도 사전 조건 점검 슬라이스는 단독 실행 가능해야 한다.
