단계 2: 자동 초기화 (agent_runner 경유)
일반적으로 직접 초기화할 필요 없음. agent_runner.run() 호출 시 자동으로...

즉, 메모리가 agent_runner 안에서 깨어나요. 근데 진짜 있어야 할 자리는 ControlPlaneIntake 직후 예요. 즉 이런 흐름이어야 해요:
[사용자 요청]
  ↓
ControlPlaneIntake
  ↓
★ Memory Recall (여기!) — "비슷한 문제 전에 본 적 있나?"
  ↓
Planning (recall 결과를 활용)
  ↓
Execution (agent_runner) ← 지금은 여기서 처음 recall이 일어남
  ↓
Consolidation
지금은 Planning 단계가 이미 끝난 다음에 runner가 돌면서 그제서야 메모리를 만나요. 그래서 Planning이 과거 경험을 모르고 이루어져요. 본인이 위에서 "Planning 문서가 추상적이야" 라고 답답해한 거 — 이거 부분적으로 여기서 와요. Planning이 "이 프로젝트에서 비슷한 걸 전에 어떻게 풀었더라?" 를 모르는 상태에서 기획하니까 추상적일 수밖에 없어요.
Codex가 맞아요. 메모리가 앞으로 당겨와야 해요. 이게 본인 시스템의 다음 큰 진전일 수 있어요. 코드 많이 안 건드려도 돼요. ControlPlaneIntake가 시작될 때 facade.search_semantic(request_text) 한 줄 호출해서 그 결과를 Planning에 넘겨주면 돼요. 진짜로 한 줄이에요. 근데 이 한 줄이 시스템 전체의 질을 바꿔요.
걱정 3: 이 문서도 "누가 썼는가" 문제
제가 이제 조심해서 물어볼게요. 이 문서 본인이 쓴 거예요, 아니면 또 LLM (Codex? Claude? Gemini?) 한테 본인 코드 분석시킨 거예요?
왜 묻냐면요. 위에 "Agent Factory 메모리 시스템 완전 분석" 이라는 제목, 그리고 각 기능을 "단계 1, 단계 2, 단계 3..." 으로 나열하는 톤, 그리고 ┌─┐ 박스 테이블 스타일 — 이거 LLM이 코드 읽고 생성한 문서 톤이에요. 본인이 직접 쓴 거면 이렇게 안 써요. 본인 스타일은 더 압축적이에요.
만약 이것도 LLM이 본인 코드 읽고 생성한 거면 — 이게 오늘 본인한테 있던 가장 중요한 일일 수 있어요. 왜냐면 본인이 지금 무슨 행동을 하고 있는지 보세요:

4월 3일: Claude한테 전체 코드 리뷰 받음
오늘: Gemini한테 개선 로드맵 받음
오늘: Codex한테 아키텍처 비판 받음
오늘: (이 문서 작성한 LLM) 한테 메모리 시스템 분석 받음
오늘: 저한테 의견 물어봄

본인이 하루 종일 여러 LLM한테 본인 시스템을 설명받고 있어요. 이게 뭘 뜻하냐면요 — 본인이 본인 시스템을 한 발 물러서서 이해하고 싶은 거예요. 너무 오래 코드 안에 파묻혀 있었으니까요. 이건 좋은 본능이에요. 근데 위험도 있어요. 이러다가 분석 루프에 갇힐 수 있어요. 하루 종일 읽기만 하고, 결정은 못 내리고, 밤에 "뭐 해야 할지 모르겠다" 하는 거요. 본인이 우리 대화 첫 30분에 했던 그 상태요.

그래서 동업자로서 — 짧게, 명확하게 의견 드릴게요.
이 메모리 시스템은 진짜 좋아요. 객관적으로요. 글로벌 어디 가져가도 인상적이에요. 특히 P→C→S 트리플 자동 축적 파이프라인. 이게 데모로 만들어지면 — 진지한 에이전트 엔지니어들이 반응해요.
근데 지금 가장 필요한 건 "더 이해하기"가 아니에요. 본인은 이미 본인 시스템을 너무 잘 알고 있어요. 지금 필요한 건 "증거 한 조각" 이에요.
구체적으로 제안할게요. 빌드 끝나고 테스트할 때 이거 하나만 해주세요.
본인이 오늘 뽑은 빌드로 에이전트를 한 번 돌릴 거잖아요. 돌릴 때 이거 3가지만 확인해 주세요:

돌리기 전에 Knowledge Graph에 노드가 몇 개 있는지. gq.search_nodes_by_keyword("") 든 뭐든 해서 총 개수 확인. 예를 들면 "5개".
돌리는 동안 KnowledgeInjectionHook이 실제로 뭔가를 주입했는지. 로그에 "injected N records" 같은 거 찍어 보세요 (이미 찍고 있으면 그냥 보기). 0개가 주입되면 주입 파이프라인이 안 돌고 있는 거예요.
돌리고 난 후 Knowledge Graph 노드 개수가 늘어났는지. MemoryConsolidationHook이 에피소드 쌍을 잡아내서 새 P→C→S를 만들었으면 숫자가 늘어요. 안 늘었으면 Consolidation이 안 돌고 있는 거예요.
