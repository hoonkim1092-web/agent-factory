코드 수정(`core/*.py`) 후 커밋 전 반드시 3가지를 수행해야 한다:

1. **Master_Blueprint.md 업데이트** — 변경 파일에 해당하는 §섹션 + §12 이력 (같은 커밋)
2. **코드 리뷰 문서 업데이트** — `python scripts/code_review_updater.py --context "변경 설명"` 실행
3. **교차검증 실행** — `af-critic` + `af-cross-review` 에이전트를 병렬로 실행하여 독립적 리뷰

**Why:** 사용자가 이 단계들을 매번 수동으로 리마인드해야 해서 불만. "왜 이것들이 계속 수동으로 돌아가는거야"라고 피드백함.

**How to apply:** 코드 수정이 완료되면 사용자가 요청하기 전에 자동으로 3단계를 모두 실행한다. Blueprint는 스킬(`af-blueprint-sync`)로 매핑 확인 후 직접 편집. 코드 리뷰는 스크립트 실행. 교차검증은 `af-critic` + `af-cross-review` 에이전트를 백그라운드로 병렬 실행.

**추가 (2026-04-10):** 설계문서(.md) 작성 후에도 교차검증을 실행해야 한다. `af-doc-qa` + `af-critic`을 병렬로 돌린다. 코드든 문서든 **산출물이 생기면 바로 검증** — 사용자가 리마인드하기 전에.

**추가 (2026-04-19) — 절대 규칙 강화:** "최초 구현 1회"가 아니라 **모든 코드 수정 커밋마다** 교차검증을 다시 돌려야 한다. BLOCK 해소 fix 커밋, ACCEPT 해소 fix 커밋, 후속 리팩토링 커밋도 예외 없이 `af-critic` + `af-cross-review` + `af-test-runner` 3개를 병렬 실행. 이전 검증에서 통과했던 코드라도 fix 과정에서 새 회귀가 들어갈 수 있으므로 매 커밋이 독립 검증 단위다. 사용자가 "왜 매번 안 돌리냐"고 재차 지적했음 — 한 세션에서도 여러 번 누락하면 신뢰 붕괴.
