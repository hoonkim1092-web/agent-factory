# Feature-Driven Workflow

## 규칙
모든 작업은 Feature 단위로 문서를 먼저 작성한 뒤 구현한다.

## 프로세스

### 1. Feature 문서 작성
경로: `docs/features/FEAT-<번호>-<이름>.md`

```markdown
# FEAT-XXX: <Feature 이름>

## 목적
- 왜 이 기능이 필요한가

## 설계
- 구조/아키텍처 변경 사항
- 영향받는 파일 목록

## 영향 범위
- 기존 기능과의 충돌 가능성
- 의존성 변경

## 체크리스트
- [ ] 문서 작성 완료
- [ ] 설계 검토 완료
- [ ] 구현
- [ ] 테스트
- [ ] 문서 업데이트
```

### 2. 문서 확인 → 구현 시작
- 문서 내용을 사용자와 확인
- 확인 후 구현 진행

### 3. 완료 후 문서 업데이트
- 체크리스트 갱신
- 변경된 부분 반영
