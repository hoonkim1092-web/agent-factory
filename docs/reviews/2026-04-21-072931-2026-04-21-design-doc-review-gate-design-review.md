#### 2. [ACCEPT] [Critical] `docs/reviews/` inclusion causes infinite review-gate recursion
- **Critic**: `docs/reviews/` is auto-generated by watcher (`scripts/pre_commit_review.py:33` `REVIEWS_DIR`, actual files like `docs/reviews/2026-04-17-224321-hook_runner-code-review.md` exist). §2.3 `_infer_type` exception `path.endswith("/code-review.md")` only matches exact `code-review.md`, not `-code-review.md` suffix. Classifying these as `design` creates infinite recursion — every auto-generated review needs its own 2-agent review to commit.
- **Cross**: not flagged
- **Judgment**: ACCEPT — concrete file evidence + obvious feedback loop. Running watcher would deadlock on its own output.
- **Action Required**:
  - Changelog L16 → remove `docs/reviews/` from design classification
  - §2.3 `_infer_type` → add `path.startswith("docs/reviews/")` exception
  - §2.3 → fix suffix match to `path.endswith("-code-review.md") or path.endswith("/code-review.md")` (or use prefix `docs/code_review/`)

#### 3. [ACCEPT] [High] `docs/patterns/` exception declared in §1.1 but not in §2.3 `_infer_type`
- **Critic**: §1.1 lists `docs/patterns/*.md` as exception but `_infer_type` only filters `/work-items/` and `/code-review.md`. Real file `docs/patterns/2026-04-18-external-api-3tier.md` would be misclassified as design.
- **Cross**: not flagged
- **Judgment**: ACCEPT — spec/impl divergence directly visible in the design code block.
- **Action Required**: Add `path.startswith("docs/patterns/")` to `_infer_type` exception, OR extract a single `_DESIGN_EXCLUDED_PREFIXES` constant used by both §1.1 spec and §2.3 logic.

#### 4. [ACCEPT] [High] `record_review_done` CLI `--tier choices=[1,2,3]` hardcoding blocks extensibility
- **Critic**: `scripts/review_gate.py:261` defines `--tier` with fixed choices. Even after removing af-doc-qa from design, the CLI agent validation via `_AGENT_TIER` dict (line 39) will reject future agents. Blocks §3.3 D1 "tier optional" intent.
- **Cross**: not flagged
- **Judgment**: ACCEPT — direct code reference with line numbers. Without this fix, v2's "tier optional" decision is incomplete.
- **Action Required**: D1 subtasks:
  - `--tier` → optional / remove `choices=[1,2,3]`
  - Replace `_AGENT_TIER` membership check with `_TRACKED_AGENTS`
  - `record_review_done(..., tier: int | None = None)`

#### 5. [ACCEPT] [High] "new-files-added" check removal not documented, regression risk
- **Critic**: Current `review_gate.py:160-164` detects new `.py` files not in tier-3 snapshot. §2.3's replacement logic drops this check entirely. Relies on `enqueue_agent_review.py:86` bumping `updated_at` to catch via stale-review, but design doesn't state this contract.
- **Cross**: not flagged
- **Judgment**: ACCEPT — silent removal of an existing safety check is a regression risk. Explicit contract needed.
- **Action Required**:
  - §2.3 add comment: "new-files-added check is subsumed by stale-review — enqueue MUST bump `updated_at` before any new file is staged"
  - §6 D0 add test case: `test_new_file_staged_after_review_completes_blocks`

#### 6. [ACCEPT] [Medium] `AF_DESIGN_GATE_DISABLED` rollback switch unimplemented in §2.3
- **Critic**: §8 mentions the flag but §2.3 `is_gate_blocked` code has no branch for it. Precedence vs `AF_SKIP_REVIEW_GATE` also unspecified.
- **Cross**: not flagged
- **Judgment**: ACCEPT — design must either specify the implementation or drop the switch to avoid ambiguity.
- **Action Required**: Pick one:
  - (a) Add concrete sketch in §2.3, e.g., `if os.environ.get("AF_DESIGN_GATE_DISABLED") == "1": required_agents -= _DESIGN_ONLY_AGENTS`, and declare precedence
  - (b) Remove §8 design-specific switch; rely on `AF_SKIP_REVIEW_GATE=1` only

#### 7. [ACCEPT] [Medium] §1.1 filename rule vs §2.3 pattern check mismatch
- **Critic**: §1.1 declares `YYYY-MM-DD-제목.md` rule, but `_infer_type` only checks `docs/` prefix + `.md` suffix. Dateless files (rule violation) get blocked by gate rather than bypassing it, creating confusion.
- **Cross**: not flagged
- **Judgment**: ACCEPT — underdetermined policy. Author must commit to one semantic.
- **Action Required**: Choose explicitly:
  - (a) Enforce `^docs/(.*/)?\d{4}-\d{2}-\d{2}-.*\.md$` pattern in `_infer_type`
  - (b) Drop filename rule mention from §1.1 and state "all `docs/` `.md` except exceptions"

#### 8. [HOLD] [Medium] `clear_committed_files` behavior on partial/mixed commits
- **Critic**: Partial commit may preserve reviews for unstaged files while snapshot drops committed ones, potentially triggering stale-review mis-fire. Mixed commits clearing all reviews is safe but undocumented.
- **Cross**: not flagged
- **Judgment**: HOLD — critic flags a real edge case but admits the clearing itself is "안전하지만" undocumented. Needs author clarification on whether current behavior is intentional before committing to a doc change or new test.
- **Question for Author**: Is partial-commit stale-review re-trigger the desired semantic, or should snapshots track per-file? If latter, is this in scope for v2 or deferred?

#### 9. [ACCEPT] [Medium] §3.5 `pre_commit_review.py` action item undecided
- **Critic**: §3.5 leaves "검토 필요" open-ended. Actual code filters `.py` only, so `.md`-only commits no-op. Should be closed out in the design, not left for implementer to rediscover.
- **Cross**: not flagged
- **Judgment**: ACCEPT — trivial but real handoff clarity issue.
- **Action Required**: §3.5 → "**변경 불필요.** `.md`-only commit은 `.py` 필터로 silently pass. review_gate와 독립 레이어."
