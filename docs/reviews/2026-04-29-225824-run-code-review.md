### Aggregated Findings (6 total)

#### 1. [ACCEPT] [High] `cwd=_ROOT`이 hook workspace를 잘못 재설정
- **Critic**: not flagged
- **Cross**: "`subprocess.run(..., cwd=_ROOT)`로 `hook_runner.py`가 AF 레포를 workspace로 감지하게 됨. `settings.local.template.json:28`은 `--workspace` 없이 `scripts/run.py cli_hook_bridge`를 호출하고, `cli_hook_bridge.py:30-31`은 fallback으로 `_PROJECT_ROOT`를 사용."
- **Judgment**: Cross가 `hook_runner.py:413-427` → `cli_hook_bridge.py:30-31` 코드 체인을 실증함. 실제 workspace가 아닌 AF 레포 루트가 hook context로 주입되어, 이벤트 라우팅이 잘못된 프로젝트로 향할 수 있다.
- **Action Required**: `caller_cwd = os.getcwd()`를 `_ROOT` 해결 전에 캡처하고, hook 위임 시 `cwd=caller_cwd`로 실행. `cli_hook_bridge` 호출 시 `--workspace caller_cwd` 추가.

#### 2. [ACCEPT] [High] `hook_runner.py` 존재 여부 미검증 — FileNotFoundError 노출
- **Critic**: "`scripts/run.py:37-38`에서 `runner` 경로 미검증. `.py` 분기(L33-34)는 `os.path.isfile` 후 `return 0`으로 처리해 일관성이 깨짐."
- **Cross**: not flagged
- **Judgment**: Critic 지적이 정확하다. 동일 파일 내 `.py` 분기는 `isfile` 체크를 하면서 hook 이름 분기(`else`)는 체크를 생략 — 코드베이스 내 기존 패턴(`hook_runner.py:418-419`)과도 불일치.
- **Action Required**: `runner = os.path.join(...)` 직후 `if not os.path.isfile(runner): print(..., file=sys.stderr); return 1` 추가.

#### 3. [ACCEPT] [High] `target` 인자 경로 트래버설 — 임의 스크립트 실행 가능
- **Critic**: "`target = ../core/evil.py` 형태 시 `scripts/` 외부 파일 실행. Claude Code hook은 외부 JSON 주입 경로가 있어 공격면 존재."
- **Cross**: not flagged (Finding #4에서 인자 전달 자체는 정상으로 판정)
- **Judgment**: 보안 이슈 — 최소 High. Cross의 Finding #4 기각(인자 전달 정상)과 충돌하지 않음; 트래버설은 인자 전달 여부가 아니라 `os.path.join` 후 경계 검증 부재 문제. 로컬 hook 컨텍스트이므로 Critical까지 에스컬레이션은 불필요하나 조기 수정 권장.
- **Action Required**: `script = os.path.realpath(os.path.join(_ROOT, "scripts", target))`; `scripts_dir`과 비교해 경계 외부면 `return 1`.

#### 4. [ACCEPT] [Medium] `scripts/run.py`가 세션 hook 중복제거 로직에서 인식 안 됨
- **Critic**: not flagged
- **Cross**: "`_is_managed_bridge_hook()`이 `hook_runner.py`/`cli_hook_bridge.py`만 인식. `settings.local.template.json:28,38,64,74,84`의 `scripts/run.py cli_hook_bridge` 패턴은 미인식 → bridge hook 2중 삽입 재현됨."
- **Judgment**: Cross가 실제 재현으로 확인. 중복 hook은 이벤트당 `cli_hook_bridge` 2회 실행 초래.
- **Action Required**: `_is_managed_bridge_hook()`에 `scripts/run.py ... cli_hook_bridge` 패턴 추가, 또는 template hook에 안정적인 `name:` 필드 부여.

#### 5. [ACCEPT] [Medium] `scripts/run.py` 디스패치 회귀 테스트 없음
- **Critic**: not flagged
- **Cross**: "`tests/` 아래 `scripts.run`/`run.py` 테스트 없음. 기존 26개 테스트는 `hook_runner.main()`만 커버."
- **Judgment**: Cross가 `rg`로 직접 확인. 새 launcher 경계(`.py` 분기, hook 이름 분기, `cli_hook_bridge` 분기)에 테스트가 전혀 없어 Finding #1~#3 수정 후 회귀 방지 불가.
- **Action Required**: `tests/test_run_dispatch.py` 추가 — `.py` 경로, builtin, `cli_hook_bridge` 세 분기에 대해 `subprocess.run` monkeypatch 테스트.

#### 6. [ACCEPT] [Medium] `subprocess.run` 예외 미처리 — OSError 시 비정상 종료
- **Critic**: "`result.returncode`에 접근 전 OSError 가능. 시그널 종료 시 음수 returncode를 `sys.exit`에 전달 → 플랫폼별 예측 불가 동작."
- **Cross**: not flagged
- **Judgment**: Critic 지적이 타당하나 Finding #2 수정(path traversal 차단) 후 실제 발생 경로가 많이 줄어든다. 그러나 `try/except OSError` 래핑은 방어적으로 필요.
- **Action Required**: `subprocess.run` 호출을 `try/except OSError`로 감싸고, 음수 returncode는 `1`로 정규화.
